Recording and sync comparison keep going when one CLI cannot run, and the review list shows its groups.

### What changed

- **A second recording CLI can take over.** **Settings → Recording** now lists Claude and Codex in the order Lore tries them, each with its own model and effort. The first one records every session. Turn the second one on and it runs when the first cannot, for example at its usage limit, after its login expired, or when it times out. **Use first** swaps the order. An answer the program rejected is not a reason to switch: the same model is asked again with the reason.
- **The sync comparison uses the same order and retries by itself.** A comparison whose model could not run is tried again after 1 minute, then at doubling intervals up to 1 hour, 8 tries in all, and the sync window says when the next try is. Earlier versions stopped at the first failure until you pressed **Try again**. The error with **Try again** and **Skip** now appears only after the last try, or when a comparison fails for another reason.
- **A comparison keeps its progress when the CLI or model changes.** Groups that are already compared stay compared, because the program checked their results. Earlier versions started over.
- **The review list shows which notes belong to which project.** **Select all** is set apart from the list, project names are heavier with their note count at the right, and notes are indented under their project.
- **The count of other changed files is gone from the review window.** Conversation copies are committed automatically and never wait for review, so the number gave nothing to act on.

### Upgrading

- Nothing changes until you turn the second CLI on: the CLI you chose before stays the only one used.
- A CLI that is not found on this PC cannot be turned on. **Set up…** on its entry opens the tools page.
- A comparison that was in progress when you upgrade starts over once.

### Limits

- Switching was tested with simulated failures, not with a CLI at a real usage limit.
- When the first CLI times out and the second one runs, one recording can take up to twice the recording timeout.
- The activity list does not say which CLI recorded a session.

### Installation

macOS: choose the Apple Silicon (`aarch64`) or Intel (`x64`) DMG and move Lore to Applications. Ad-hoc signing is enabled; Apple Developer ID and notarization are not configured. macOS may still require **System Settings → Privacy & Security → Open Anyway** after attempting to open the app.

Windows: use the `x64-setup.exe` installer. Linux x64: use the AppImage for in-app updates, or install the DEB manually. Existing memory, settings, and update keys are retained.
