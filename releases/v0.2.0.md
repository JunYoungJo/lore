Sync now runs without any action from you, and never holds recording.

### What changed

- **Notes are committed automatically.** When a recording finishes, Lore commits what it wrote. Sync no longer refuses to run because of uncommitted notes.
- **Diverged histories merge automatically.** When this PC and another PC both have new commits, Lore merges them and pushes. Notes changed on different PCs, or in different places of the same note, are combined without a review.
- **Same lines changed on both PCs: both are kept.** Lore keeps the lines from both PCs and lists the note under **to check**. If one PC deleted a note the other edited, the edited note is kept and listed.
- **Recording never waits for sync.** Notes to check, a failed sync, or a running model comparison do not pause recording.
- **Sync right after recording.** With **Auto-sync** on, Lore syncs when the recording queue becomes idle and every five minutes. Auto-sync is still off by default.
- **Quiet retries.** A failed sync is retried on the next cycle. Lore notifies you only after three failures in a row.
- **Model comparison runs afterwards, on fewer notes.** After a sync, only the notes that both PCs changed are compared, in the background. Disagreements are added to the same list with quoted sources and wordings to choose from; applying one is a normal commit. A reply the program rejects is sent back to the model with the reason instead of stopping the comparison, and quotations from the merged note are accepted.
- **Review is optional.** The review window now shows notes recorded on this PC since your last review and has **Mark reviewed** instead of a commit message. Notes received from other PCs do not wait for review here.

### Upgrading

- A sync review left waiting by 0.1.x no longer holds anything. On the next sync Lore merges both histories as described above; the old review data is kept in the app data folder as `superseded-*.json`.
- Notes that were uncommitted when you upgrade stay in the review list and are committed by the next recording or sync.
- The memory repository needs `user.name` and `user.email` configured, because Lore now creates commits by itself. Files you do not want shared must be in `.gitignore`: every other file in the memory folder is committed and pushed.
- CLI: `lore-cli sync` now takes `status`, `now`, `compare`, `resolve <item-id> <option>`, and `dismiss <item-id>`. The `check`, `analyze`, `preview`, `apply`, and `resume` commands were removed.

### Limits

- Keeping both PCs' lines can leave repeated or disagreeing lines in a note; that is why the note is listed. Edit the note to fix it.
- The model comparison uses the selected CLI account's allowance and can miss contradictions. It runs automatically whenever both PCs changed the same note.
- Histories with no single common base cannot be merged automatically. Merge them once with a Git tool, then sync again.
- Review state and the list of notes to check are kept per PC and are not shared.

### Installation

macOS: choose the Apple Silicon (`aarch64`) or Intel (`x64`) DMG and move Lore to Applications. Ad-hoc signing is enabled; Apple Developer ID and notarization are not configured. macOS may still require **System Settings → Privacy & Security → Open Anyway** after attempting to open the app.

Windows: use the `x64-setup.exe` installer. Linux x64: use the AppImage for in-app updates, or install the DEB manually. Existing memory, settings, and update keys are retained.
