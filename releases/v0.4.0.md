Lore writes into the notes only what the session marked and you approved, and it can clean up a folder of notes.

### What changed

- **Only what the session marks becomes a candidate.** With each prompt, a hook tells Claude Code and Codex how to mark a decision you made, a correction to how the agent works, or a lesson the work established, at the moment it happens: `lore-cli mark <decision|correction|lesson> "<sentences>" --by <user|agent> --said "<your words>"`. The session says whose it is (yours, or the agent's proposal you approved, or the agent's finding) and quotes your words. Nothing is looked for in the conversation afterwards.
- **A mark can name the note it changes or ends.** When the session read a note with qmd and knows that a decision changes it, it adds `--updates <note>` or `--retires <note>` with `--quote "<the note's words>"`. Lore checks that the note exists and holds those words, and the Candidates window shows that approving edits or ends that note.
- **A mark can be replaced or withdrawn later in the session.** `--replaces <id>` puts a new version in place of an earlier mark, and `lore-cli mark cancel <id>` withdraws one. A candidate that already waits from before a compaction leaves the list; one you already decided stays as you decided it.
- **Your words are checked.** A quoted word of yours is kept only when Lore finds it in what you said in the session before the mark. Words it cannot find are never shown as yours.
- **Notes say whose a statement is.** A proposal of the agent that you approved is written as the agent's proposal and your approval, with both in the note's Sources list, not as something you said. A finding of the agent you did not confirm is written as the agent's finding.
- **Candidates window.** Candidates are listed by session and decided one at a time with keys or buttons: approve, discard, later, reword, this project or all projects. Decisions are applied together. The window says first what approving does: add to the notes, edit a note or delete a note, with the note's passages. The Written tab lists what each approved batch wrote, for 30 days.
- **Automatic approval (off by default).** A candidate that waited the set number of days is approved as it stands.
- **The recording model reads the notes itself.** When a session is read and when approved candidates are written, the model searches and reads the notes of the project and of `common/` with qmd and file tools, read-only, with your own CLI setup but without hooks, plugins, skills, your MCP servers or sub-agents.
- **Cleaning up notes.** The tray window lists folders with ten or more notes changed since their last cleanup. The cleanup window cleans them one after another, merges repeated notes, removes notes whose subject is gone, moves working rules into the shared notes, and can undo a folder's last cleanup or merge one project folder into another. "Clean up automatically" is off by default.
- **Review window.** The header of a note keeps its place, with a "Changes only / Whole note" choice for every note.
- **Removed:** the setting "Conversation read per step". No part of the conversation is sent to a model any more, so a session is read to its end in one step.

### Upgrading

- Existing notes, settings and the queue are kept.
- From a build that already had the prompt hook and the mark allow rules, nothing needs reconnecting: the hooks run the same `lore-cli`, and the new instruction comes from it.
- From v0.3.2, **Manage Lore** shows Claude Code and Codex as "Needs repair", because the prompt hook and the allow rules for `lore-cli mark` are new. Repair them there; Codex asks you to trust the new hooks with `/hooks`.
- Sessions that are open while you upgrade: marks they made in the earlier one-sentence form are not read.

### Limits

- What a session does not mark is not offered. How much is offered depends on how well the agent follows the instruction it gets with every prompt.
- The new preparation and writing prompts were tested with simulated model answers, not yet against Claude or Codex.
- A mark names one note. A change to two notes needs two marks.

### Installation

macOS: choose the Apple Silicon (`aarch64`) or Intel (`x64`) DMG and move Lore to Applications. Ad-hoc signing is enabled; Apple Developer ID and notarization are not configured. macOS may still require **System Settings → Privacy & Security → Open Anyway** after attempting to open the app.

Windows: use the `x64-setup.exe` installer. Linux x64: use the AppImage for in-app updates, or install the DEB manually. Existing memory, settings, and update keys are retained.
