Notes are written for the agent that reads them later, in the language you work in, and the windows no longer behave like web pages.

### What changed

- **Notes state what is true now, not what happened in a session.** The recording model is asked for what a later session needs: your decisions and their reasons, corrections to how the assistant worked, problems with their cause and fix, and open issues someone raised. It writes one note per topic, puts the decision or lesson first, and leaves out the course of the work and details that git, CI and logs already hold. Titles name the topic and its conclusion and carry no dates.
- **Notes follow the language of the session.** A session in English produces English notes, a session in Korean produces Korean notes. Earlier versions always wrote Korean. An existing note keeps its language when it is edited.
- **What agents said to each other stays out of the notes.** Instructions from an orchestrator and reports from sub-agents are still sent to the recording model, so it can tell what your own words refer to, but who was asked to do what is not recorded. A technical finding in an agent's report is recorded as a lesson marked as an assistant report.
- **A section can be restated.** The recording model can replace one `## ` section of an existing note with its current state instead of appending a dated account to it.
- **A rejected proposal is retried with the reason.** When the program rejects what the model proposed, the next attempt is told why. A read request the sync comparison cannot serve is sent back the same way instead of stopping the comparison.
- **The recording model gets less to read.** Existing notes are sent without their source lists.
- **English throughout.** The prompts, the `## Sources` heading of a note, the speaker labels in session copies and the detailed documentation are now English. `README.ko.md` remains.
- **Windows behave like app windows on every platform.** The browser's right-click menu, page zoom, reload, find and print shortcuts, middle-button scrolling, dragging content out, spelling marks and autofill are off in every window. On macOS, labels and buttons can no longer be selected like page text. Checkboxes no longer show a focus ring after a modifier key; rings appear after Tab.
- **Checkboxes, radio buttons and disclosure arrows are drawn by Lore**, so they look the same on macOS, Windows and Linux.

### Upgrading

- Notes written by earlier versions are not rewritten by the app. Their source list keeps its Korean heading and is still read; a note gets the `## Sources` heading the next time it is changed.
- Session copies under `sources/` get English speaker labels the next time their session is recorded.
- A qmd collection that already exists keeps the description it was created with.
- Install this version on every PC that shares the memory repository before recording there again. An older version does not recognize `## Sources` and adds a second source list to a note it edits.

### Limits

- What is worth recording, and whether a statement is your decision or an assistant's report, is still the recording model's judgment. A note can still retell part of a session, and a decision can still be missed; the linked source conversation is the check.
- The model selection lists in Settings open the platform's standard dropdown.
- The window changes were measured in WebKit and Chromium and by automated tests, not in each platform's installed app.

### Installation

macOS: choose the Apple Silicon (`aarch64`) or Intel (`x64`) DMG and move Lore to Applications. Ad-hoc signing is enabled; Apple Developer ID and notarization are not configured. macOS may still require **System Settings → Privacy & Security → Open Anyway** after attempting to open the app.

Windows: use the `x64-setup.exe` installer. Linux x64: use the AppImage for in-app updates, or install the DEB manually. Existing memory, settings, and update keys are retained.
