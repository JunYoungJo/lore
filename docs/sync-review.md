# 여러 PC의 기억 동기화 검토

## 처음 연결하기

각 PC에서 동일한 기억 Git 저장소를 clone하고, 앱의 기억 저장소 경로를 그 PC의 경로로 지정합니다. 현재 브랜치에 remote/upstream이 연결돼 있어야 합니다. 기존 저장소라면 `git remote -v`, `git branch -vv`로 확인합니다. 앱은 remote나 인증 정보를 새로 만들지 않습니다. 터미널에서 fetch/push가 가능하도록 먼저 인증합니다. Git 2.38 이상이 필요합니다.

공유되는 것은 **기억 저장소에 커밋한 모든 파일**입니다. 기억 문서뿐 아니라 `sources/` 대화 사본의 인용하지 않은 부분도 포함됩니다. 큐·설정·모델 실행 자료와 qmd 색인은 PC별 앱 데이터에 둡니다. 기존에 Git으로 추적한 캐시·개인 파일은 별도로 정리해야 합니다. 소스 프로젝트의 고정 ID와 qmd MCP 연결은 [여러 PC에서 사용하기](multiplatform.md)를 따릅니다.

## 화면에서 하는 일

1. 상태 화면에서 **동기화**를 엽니다. 새 기록이 있으면 **로컬 변경 검토·커밋**으로 먼저 커밋하고 그 창을 닫습니다. 미커밋·미추적 파일이 있으면 동기화를 진행하지 않습니다.
2. **공유 저장소 확인**을 누릅니다. 한쪽만 앞서 있으면 기존 커밋을 가져오거나 보낸 뒤 이 PC의 qmd 색인을 갱신합니다. 양쪽 이력이 갈라지면 Git 객체로 병합안을 만들고 현재 문서·브랜치·stage는 유지합니다.
3. **모델로 비교**를 누릅니다. 기존 기록 모델 설정의 Codex 또는 Claude를 사용합니다. 마지막 공통 기준·양쪽 문서·Git 병합안과 연결된 대화 사본을 비교합니다. 같은 프로젝트에서 서로 다른 파일을 고친 경우와 common 변경도 비교 대상입니다. 서로 독립된 프로젝트의 변경은 모델 호출 없이 병합 미리보기를 제공합니다.
4. 충돌 후보마다 **양쪽 근거와 인용**, **왜 확인이 필요한지**, **선택지**를 봅니다. 예를 들어 ‘팝업 없이 로그만’과 ‘오류 팝업 표시’ 중 앞으로 쓸 방침을 선택합니다. 기존 문서를 직접 편집할 필요는 없습니다. 단일 수정으로 구성된 선택안은 필요할 때 **선택한 안의 문구 직접 정리**로 고칠 수 있습니다.
5. 모든 항목을 선택하면 **최종 문서 미리보기**가 나옵니다. 전체 결과를 확인하고 **이 내용으로 반영·공유**를 누릅니다. 앱이 다시 원격 상태를 확인하고, 양쪽 이력을 부모로 가진 병합 커밋을 적용한 뒤 검색을 갱신하고 push합니다. 미리보기와 다른 선택 내용은 반영하지 않습니다.

모델은 의미 충돌 후보와 해소안을 제안합니다. 프로그램은 인용문이 실제 제공 자료에 있는지, 수정할 구간이 정확히 한 번 일치하는지, 기존 근거 링크가 남아 있는지 등을 검사합니다. 문장의 진실·적용 범위·최신 결정 여부까지 이 검사로 증명하지는 않습니다. 날짜가 늦다는 이유만으로 새 방침을 자동 채택하지 않습니다. 사용자가 근거를 보고 최종 판단합니다.

## 기다리기와 재시도

- **나중에:** 창을 닫아도 양쪽 원문·모델 결과는 보존됩니다. 검토가 남아 있으면 새 기억 반영은 대기합니다. Claude·Codex 작업과 훅의 큐 접수는 계속됩니다. 앱을 다시 켜도 검토 상태가 이어집니다.
- **5분마다 자동 동기화:** 기본 꺼짐입니다. 켜면 커밋된 이력을 주기적으로 확인합니다. 분기된 이력은 검토 대기와 알림까지만 처리하고 모델은 자동 호출하지 않습니다. 미커밋 기록도 자동 커밋하지 않습니다.
- **다른 PC가 먼저 반영:** 승인 전에 원격이 바뀌었으면 **공유 저장소 확인**으로 다시 비교합니다. 기존 비교 자료는 앱 데이터에 별도 보존됩니다.
- **검색 갱신 실패:** 문서가 이미 반영됐는지 상태에 표시합니다. qmd 설치·경로를 고친 뒤 **반영·검색 갱신 다시 시도**를 누릅니다. 모델을 다시 호출하거나 문서를 중복 반영하지 않습니다.
- **전송 실패:** 로컬 결과는 보존되고 **전송 다시 시도**로 재개합니다. 그동안 새로 생긴 미커밋 문서는 이 전송에 들어가지 않습니다. 원격이 앞서 전송이 거부되면 **공유 저장소 확인**으로 새 이력을 비교합니다. 강제 push는 하지 않습니다.

앱은 기록·검토 커밋·동기화를 같은 실행 잠금으로 보호합니다. 앱 밖에서 실행한 Git 도구나 다른 PC를 잠그지는 않습니다. 반영 직전의 변경 검사도 외부 프로세스의 임의 동시 작업까지 완전히 막지는 못하므로, 앱 동기화 중 외부 Git 작업은 끝난 뒤 진행합니다.

## 첫 구현의 지원 범위

일반적인 기억 Markdown의 내용 충돌을 지원합니다. 대화 사본 충돌, 삭제·이름 변경 등 텍스트 선택으로 해소할 수 없는 충돌, 공통 기준이 없거나 여러 개인 이력은 외부 Git 도구에서 먼저 해결하고 **공유 저장소 확인**을 다시 누릅니다. 한 번에 모델에 전달할 문서·근거 자료가 160,000자를 넘으면 누락해서 판단하지 않고 중단합니다. 큰 충돌을 나눠 처리하거나 외부에서 먼저 정리해야 합니다. 모델이 놓치는 의미 충돌과 프로젝트 사이의 숨은 의존 관계는 남을 수 있습니다.

PC별 앱 데이터의 `sync/<기억 경로 해시>/pending.json`에 진행 상태를 저장합니다. 완료·재비교 자료도 같은 폴더에 남고, 승인 커밋은 로컬 `refs/qmd-memory/sync/`에 보존됩니다. 이 자료는 Git 동기화 대상이 아닙니다.

CLI는 트레이 앱을 끈 뒤 사용합니다. `sync status`, `sync check`, `sync analyze`, `sync preview <선택.json>`, `sync apply <계획ID> <선택.json>`, `sync resume`을 제공합니다. 선택 파일은 `[{"issue":0,"option":0,"customText":null}]` 형식이며 모든 항목에 대한 선택이 필요합니다. `preview`로 확인한 계획 ID와 같은 선택 파일을 `apply`에 넘깁니다. 일반 사용은 화면에서 진행하는 편이 간단합니다.
